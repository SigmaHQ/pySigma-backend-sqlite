# SQLite backend correctness and Sigma 2.1 conformance plan

**Target.** Start from `wagga40/main` at `e37c71c`. A rule should declare exactly what it needs to execute. A correlation’s standalone SQL and materialized plan should agree on alerts, metrics and evidence. The conformance target is the published Sigma 2.1.0 specification. Record differences where SigmaHQ’s authoring guide and pySigma accept a different spelling or interpretation. [Reviewed source](https://github.com/wagga40/pySigma-backend-sqlite/tree/e37c71cc25b30ced05cd5b820f189583e35f6d89) · [Sigma 2.1.0](https://github.com/SigmaHQ/sigma-specification/releases/tag/v2.1.0)

**Release proposal.** Land the three correctness changes below before tagging 2.2.0. Deliver new SQL features as independently reviewable follow-ups. Keep the existing portable 2.x defaults and offer stricter behavior explicitly. A default switch affects plain SQL clients as well as Zircolite and deserves a separate compatibility decision. **Decision (2026-11-21):** three conformance fixes change default results and are listed in the migration guide. Calendar weeks follow ISO numbering, and `week_mode="legacy"` restores `%W`. `windash` expands every dash position in a value with at most three dashes and falls back to pySigma's word-start expansion beyond that. `re|startswith` and `re|endswith` stop at field boundaries. The last two have no opt-out. This plan covers the backend repository. Consumer checks use released software and disposable fixtures. SigmaHQ synchronization, downstream releases and `typing_extensions` work are outside this delivery.

## Release blockers for 2.2.0

- [ ] **1. Keep emitted predicates paired with their source conditions.** In `sigma/backends/sqlite/sqlite.py`, adapt the existing conversion hook so every retained detection predicate has its original condition index, converted SQL and `ConversionState`. Capture omissions caused by pipelines and callbacks. Render each Zircolite entry’s fields, source table, Channel/EventID bounds, full-text declaration and SQL functions from that same record. In `correlation.py`, union the records for the predicates actually used, plus grouping, timestamp, identity and metric fields. Preserve pySigma’s raw predicates for references, standalone output for `generate`, and a single application of each pipeline and callback. Scope retained data to its conversion, including direct rule-conversion callers.

  **Proof.** In `tests/test_keyword_search.py`, `test_cidr_exact.py` and `test_correlations.py`, drop the first, middle and all conditions through the standard pipeline with and without a callback. A surviving keyword requires schema 3 and its text column, an IPv4 /24 in exact mode requires schema 4 and its function, and an ordinary EventID requires schema 2 and its own field. Reverse the fixture so a callback drops the keyword or /24. Both correlation paths must then find one alert on a connection containing only the retained fields and no custom functions. Cover nested references, `generate`, and reconversion on the same instances. For structured exports, accept identity and drop callbacks. If a callback substitutes different SQL for a detection or a finished correlation, and the replacement's dependencies or equivalent plan cannot be established, raise a rule-scoped conversion error. Test replacing `EventID=1` with a different field and replacing a correlation with a zero-row query. Preserve plain SQL callback behavior. Document this structured-output restriction.

- [ ] **2. Propagate failures through the correlation graph.** In `sqlite.py` and `correlation.py`, record a failed conversion for the current run, including pipeline failure on an intermediate correlation. Check that state before descending into a referenced node. Successful reference-only rules can legitimately emit no standalone entry. Preserve the original exception on the failing rule and include the parent and failed dependency in the dependent error. Clear transient failures and pending plans on retry, skipped output and exceptions.

  **Proof.** In `tests/test_correlations.py`, reject the middle node of `base → child → parent` while an independent rule matches. In collection mode only the independent rule produces results, and both child and parent have identifiable errors. In fail-fast mode the source error surfaces. A subsequent successful conversion of the same objects emits the expected alert. Also cover a shared failed dependency and a successfully suppressed child.

- [ ] **3. Make bounds, identifiers and numeric validation safe for consumers.** In `sqlite.py`, emit integer EventID bounds when the accepted literals map unambiguously to the same event identifiers. Preserve the shortest safe bound, the restored Sysmon lists and correctly decoded literal Channel values. If validity depends on an unknown affinity, collation or consumer coercion, widen that bound. Accept SQLite table names with one or two nonempty components and quote each component. Keep constructor validation immediate. Convert an invalid rule-specific pipeline override into a collectable Sigma error. For numeric comparisons, reject embedded NUL in TEXT before applying the existing numeric conversion.

  **Proof.** Extend `tests/test_backend_sqlite.py` and `test_sqlite_minimum.py`. Integer event 1 must survive the condition combining `[1, 2]` and `'1.0'`, and every emitted EventID must be readable by the historical integer consumer. Cover ambiguous values, escaped wildcards in literal channels, and the two restored corpus filters. Accept `main.logs`, reject `a.b.c`, and keep an independent valid rule after a bad table override. For `gt: 10`, match `'11'` and reject `'11\0junk'` on SQLite 3.38.0 and 3.54.1. Preserve the existing accepted numeric spellings and integer precision tests.

**2.2.0 release decision.** Promote the incident reproductions into tracked tests. Run the existing Python 3.11–3.14 matrix, the minimum and current SQLite runtimes, and the eight pinned corpus audits across four profiles and two CIDR modes. Diff entry-level schema versions, fields, bounds, full-text and function declarations against the merged baseline. Explain each changed group. Compare event and evidence identities on populated databases. Build the wheel and sdist, exercise a schema-2 IPv4 /32 export with Zircolite 4.7.1, and validate schema-4 examples through the backend runtime. The release is ready for maintainer review when all three fixes pass and the output differences are accounted for.

## Detection semantics and consumer requirements

- [ ] **CIDR.** Use existing `cidr_mode=exact` for the strict membership contract. Keep its built-in IPv4 /32 path and function preflight for other exact networks. Identify expanded mode as a spelling-based compatibility option in the support table. Reuse the independent all-prefix oracle and benchmark the actual emitted event query and plan on indexed and unindexed input. Include IPv4/IPv6 /0, invalid text, mapped addresses, padded IPv6, negation and NULL. A migration to exact emits new prerequisites only for entries that use them. [CIDR specification](https://sigmahq.io/sigma-specification/specification/sigma-appendix-modifiers.html#ip-internet-protocol-modifiers)
- [ ] **Case-insensitive text.** Specify three environments in the README: stock BINARY columns, ASCII NOCASE, and an opt-in Unicode-capable connection. For the last, implement and validate deterministic matching helpers for literals, wildcards, field references and keywords. Specify case folding and wildcard units together so `?` still consumes one source character. Preserve `cased`, explicit regex flags and literal escaping. Define the same equality semantics for tuple counting and grouping when that option is selected. Test `CAFÉ/café`, multi-code-point folds, literal underscores, one-character wildcards and negation.
- [ ] **Presence versus NULL.** Add an opt-in backend contract for a per-event source of field presence, for example a configured JSON array of present flattened field names captured before NULL widening. Compile `exists` against it and validate availability and representation before execution. Specify field mapping, quoted/dotted names, duplicate keys and per-table source selection. Test absent, present-null, empty string and a nonempty value, for both `exists: true` and `false`. Existing flattened databases require suitable source data or re-ingestion for this feature. [Sigma field existence](https://sigmahq.io/sigma-specification/specification/sigma-appendix-modifiers.html#generic-modifiers)

The exact-sum helper, Unicode matching and field presence affect `sqlite.py`, `runtime.py`, `correlation.py` and the output-format contract. Structured schemas 2–4 keep regex registration as their documented connection-level prerequisite. For the new contract, declare `regexp` per emitted predicate, include it in referenced correlation plans and test behavior on unregistered connections and NULL input. Current schema 4 recognizes only the CIDR function in its function list. Introduce a new schema/plan version for entries requiring a new helper or presence source, validate it before execution and continue to read versions 2–4. Test the backend runtime as a reference consumer, and measure scans, index use and ingestion/storage cost on disposable fixtures. General rollout to Zircolite or generated rulesets depends on those consumers supporting the new contract.

## pySigma parsing and published syntax

The normal Python and sigma-cli entry points receive already-parsed rules. Revalidate the following fixtures against the installed minimum and latest supported pySigma. Where the original distinction survives, implement it in the backend. Where parsing has already rejected or altered it, preserve the fixture and adopt a compatible pySigma release when available. Rewriting generated SQL cannot recover discarded input. The backend plan does not require a global modifier-registry patch or a second YAML parser.

## Verification and handoff

1. In each change, reproduce the behavior on the baseline, add a failing fixture, implement the change, then compare actual event IDs or correlation metrics and evidence. Run `poetry run pytest -q`. Use the existing CI configuration to exercise SQLite 3.38.0 through Python and repeat on 3.54.1 or a tested successor.
2. Run `tools/audit_corpus.py` on the pinned Sigma revision `088855f00b65a19e345b09c1619272b44f92fea4`, with raw, Windows Sysmon, Windows audit and Linux profiles in expanded and exact modes. Use `--fulltext-field _sigma_fulltext`. Retain preparation totals and separately record execution results for the conformance fixtures.
3. Use `tools/benchmark_cidr.py` and `tools/benchmark_correlations.py` for performance-sensitive changes. Compare medians on the same machine, SQLite build, data and indexes. Check matched event IDs and evidence before interpreting timings. Package the candidate with `poetry check --lock` and `poetry build`, then smoke-test plugin discovery and both output formats from the built wheel.
4. Review each proposed release against the support table. Publish migration examples for behavior that changes existing results. Keep the backend fixes, later consumer adoption and eventual ruleset regeneration independently reviewable.
